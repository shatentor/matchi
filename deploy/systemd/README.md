# Автозапуск через systemd (без sudo)

Юниты пользовательские, поэтому root не нужен. Все пути внутри файлов —
абсолютные и жёстко привязаны к `/home/nikita`: systemd не раскрывает `~` и не знает
переменных окружения оболочки. При переносе на другую машину или другого пользователя
пути надо поправить.

## Установка

```bash
mkdir -p ~/.config/systemd/user
cp deploy/systemd/matchi-*.service deploy/systemd/matchi-*.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now matchi-postgres matchi-redis matchi-bot matchi-backup.timer
```

Обязательный шаг, иначе всё поднимется только после входа в систему и умрёт при выходе:

```bash
loginctl enable-linger $USER      # проверить: loginctl show-user $USER | grep Linger
```

## Что делает каждый юнит

- `matchi-postgres` — кластер в `~/.local/share/matchi-pg` на порту **5433** (5432 занят
  SSH-туннелем к другой базе). `ExecStartPost` ждёт готовности через `pg_isready`: без этого
  бот стартовал бы раньше базы и падал на создании пула, потому что для `Type=simple` systemd
  считает юнит поднятым сразу после `fork`, а не после готовности принимать соединения.
- `matchi-redis` — `~/.local/bin/matchi-redis-server`, копия бинарника из pip-пакета
  `redislite`. Копия, а не путь в `.venv`, чтобы пересоздание виртуального окружения не ломало
  автозапуск. Поставите Redis из apt — выключите этот юнит, оба слушают 6379.
- `matchi-bot` — сам бот, `Restart=always`. Зависимости объявлены через `Wants`, а не
  `Requires`: если база или Redis на секунду отвалились, бота не нужно гасить насовсем, он
  перезапустится и переподключится. `StartLimitBurst` не даёт крутить перезапуск бесконечно,
  когда сломано что-то серьёзное.
- `matchi-backup.timer` — ежедневный бэкап в 04:00 с `Persistent=true`: если в это время
  машина спала или была выключена, бэкап снимется при следующем включении, а не пропустится.

## Повседневное

```bash
systemctl --user status matchi-bot
journalctl --user -u matchi-bot -f          # живой лог
systemctl --user restart matchi-bot          # после правки кода
systemctl --user start matchi-backup         # бэкап прямо сейчас
systemctl --user list-timers 'matchi*'
```

`python main.py` руками больше запускать не нужно: два процесса будут тянуть апдейты одного
бота и мешать друг другу.

## Чего эта настройка не решает

Машина — ноутбук. При закрытии крышки система засыпает, и бот не отвечает, пока она спит;
Telegram держит необработанные апдейты около суток, поэтому после пробуждения они дойдут, но
всё это время бот выглядит недоступным. Бэкапы лежат на том же диске, что и база, — от потери
диска это не спасает, копию стоит уносить наружу. Для сети, которой пользуются другие люди,
правильный хост — небольшой сервер, а не ноутбук.
