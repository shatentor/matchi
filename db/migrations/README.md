# Миграции схемы

- Новая миграция — файл `NNN_описание.sql` в этом каталоге, где `NNN` — следующий
  свободный трёхзначный номер (`004`, `005`, ...). Номера не переиспользуются,
  применённый файл не редактируется: исправление оформляется новой миграцией.
- Применяются по возрастанию номера, каждая в своей транзакции и только один раз;
  версии учитываются в таблице `schema_migrations`.
- Пиши идемпотентно (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`,
  `INSERT ... ON CONFLICT DO NOTHING`) — так миграция безопасна и на живой базе.
- Применить всё неприменённое: `python db/migrate.py` (из корня проекта).
- Посмотреть состояние, ничего не меняя: `python db/migrate.py --status`.
- Старый `create_db_tables.py` оставлен для совместимости, но новые изменения
  схемы идут **только** через миграции; `db/sql_templates.sql` он и повторяет.
